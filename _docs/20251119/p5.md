Analyzing how graph-ready metadata intersects with folder hierarchies so we can decide what to keep.

Graph metadata is useful even with nested folders because it captures relationships that traditional folder trees can’t: cross-folder references, entity-to-entity links, and conversation/file associations that go beyond parent-child inheritance.
You still derive folder ancestry via traditional metadata (e.g., folderId, ancestor IDs). That structure is fast for “show children”, “move folder”, etc. Graph metadata supplements this with semantic edges like “Document A references Dataset B” or “Conversation X used File Y”.
With a hybrid search, you can boost or filter ES hits using both folder filters and graph context. Example: user selects a folder subtree; the query grabs folder IDs from the relational side and still benefits from graph edges that point to related documents outside that subtree if they’re semantically relevant.
Graph metadata also gives you future flexibility for features like “show me related documents” or knowledge graph visualizations without re-ingesting content.
In short: keep folder hierarchy in relational metadata for quick traversal, and treat graph-ready metadata as an additive layer for richer retrieval and analytics.
